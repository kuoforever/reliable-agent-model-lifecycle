# Step protocol

> **Status: current module of teaching protocol v1.**

Before a non-trivial step, explain the objective, required model/data/systems
concepts, why it is next under [project status](../../../PROJECT_STATUS.md), the
pre-registered evidence expected, and what failure would mean.

During execution, explain consequential tensor shapes/dtypes, dataset identity,
artifact hashes, command flags, controlled variables, resource bounds, and
design trade-offs. Summarize repeated builder, validator, and matrix operations.

After the step, report the result, what it proves, what it does not prove,
alternative explanations, negative results, one interview question, and whether
the result belongs in [resume evidence](../resume/).

> Before: Objective ... Variable ... Locked inputs ... Expected gate ... Failure means ...

> After: Result ... Proves ... Does not prove ... Negative result ... Next gate ...
